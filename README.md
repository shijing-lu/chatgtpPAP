# 批量生图助手 · ChatGPT / Gemini（Chrome 扩展）

把一整批提示词丢给 **ChatGPT 或 Gemini** 官网，它逐条自动生图、自动判断这张图好了没有、自动下载到指定文件夹，然后接着跑下一条，直到全部完成。

不需要 API Key，走的是你自己已登录的页面。每个批次各自绑定一个「工作站点」，互不串台。

**两个站点怎么用：**
- **ChatGPT**：`chatgpt.com` / `chat.openai.com`，默认站点，行为与旧版一致
- **Gemini**：`gemini.google.com`，在队列页「工作站点」下拉里选 Gemini 并点「保存批次设置」，然后打开一个 Gemini 对话页再点「开始」
- Gemini 生成图是 `generated-image` 容器里的预览图，插件会点容器里的「Download full size image」拿**全尺寸原图**，再按批次目录与命名模板归位；不会新开标签页
- 批次只接管同站点的标签页，跨站点领任务会被直接拒绝；运行中不能切换工作站点

**队列提示词复制**：每条右侧有「复制」，列表工具条有「复制选中 / 复制全部」。复制的是后台保存的**完整原文**（列表里只是 240 字预览），多条之间用 `---` 分隔，可直接贴回 Markdown 导入。

---

## 一、安装

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（含 `manifest.json` 的那一层）
4. 在 chrome 工具栏点扩展图标 → 右侧弹出侧边栏

> 需要 Chrome 114 及以上。

## 二、批次（分组）与简单模式

### 先建批次

侧边栏顶部的下拉框就是批次切换器。一个批次 = 一个主题 / 一个任务，它自己带着：

- **名称**（同时决定默认下载子目录）
- **工作站点**（ChatGPT / Gemini，决定这个批次在哪类标签页上执行）
- **下载目录**（可以单独指定，留空就是 `基础目录/批次名/`）
- **前提设定**（这个批次专属的上下文，见第四节）
- **运行状态**、**独立窗口**

点「＋ 新建」建一个，再在下方改名、选工作站点和设目录，点「保存批次设置」。不同主题（产品图 / 风景图 / 客户A）就建不同批次，互不干扰；新批次会继承当前下拉里选的站点。**批次运行中不能切换工作站点**，要先暂停或停止。

### 再往里加提示词

**方式一：一条一条加**

1. 输入框写一条提示词，点右侧 **＋**，加入**当前选中的批次**，输入框自动清空
   - `Ctrl + Enter` / `⌘ + Enter` 等同于点 ＋；`Shift + Enter` 换行
2. 重复加到你满意为止

**方式二：从 Markdown 批量导入**

点输入框下方的「从 Markdown 导入」，会弹出一个导入面板，三条路随便走：

- 点「选择文件」上传 `.md` / `.markdown` / `.txt`
- 把文件直接拖进虚线框
- 把 Markdown 内容粘进去（面板里按 `Ctrl+V`，或贴在文本框里）

规则只有一条：**一个代码块 = 一条提示词**，代码块里的内容就是这条提示词的正文；文件里有几个代码块，就导入几条。

````markdown
```
白色无线耳机，柔和侧光，浅景深
```

```
黑色石英手表，深色大理石台面
```
````

上面这段会导入 2 条。几个细节：

- 代码块前面的标题、说明文字、列表都不参与，只取代码块内部
- 代码块里写了语言标记（```text）不影响，照样只取正文
- 用四个反引号包住三个反引号，可以正常保留提示词里自带的 ``` 片段
- 代码块内部的首尾空行会被去掉，中间换行保留
- 没闭合的代码块按「一直到文末」处理，并提示你
- 空代码块会被忽略，不会产生空任务
- 导入前会显示「识别到 N 条」和前 8 条的预览，先核对再点「导入」
- 导入是**追加**到当前批次末尾，不会清空已有提示词；单批次上限 2000 条

3. 点「开始」，它会**直接在你已经打开的那个 ChatGPT 标签页里跑**，不会新开窗口

> 只有当你没有可用的 ChatGPT 标签页时才会新建一个（建在当前窗口里，不另开窗口）。
> 同时跑多个批次时，每个批次占一个标签页：先占用空闲的 ChatGPT 标签页，不够才再开。

跑的过程中：

- 每个条目显示状态：待生成 / 发送中 / 生成中 / 下载中 / 已完成 / 失败 / 待确认
- 单条操作：「重试」「跑这条」「跳过」
- 左侧复选框 + 「删除选中」批量删除（二次确认，执行中的不能删）
- 「清理」移除已完成 / 失败 / 跳过
- 「暂停」＝ 当前这张跑完就停；「停止」＝ 立刻中断并退回待生成

## 三、高级模式：提示词 + 参考图

侧边栏第二个标签页「高级」，用法和简单模式一样，只是可以额外挂参考图。

1. 写提示词
2. 加参考图，三种方式任选：点「＋ 参考图」选文件、把图片拖进页面、或者**直接 Ctrl+V 粘贴**（截图工具截完就能贴）。最多 4 张，缩略图列在下面，点 × 可移除
3. 点 **＋** 加入队列 —— 提示词和图片就绑定成一条任务

执行时：先打开新对话 → 发前提（如果配了，**每条都等 ChatGPT 回复写完才发下一条**）→ **把参考图上传到输入框并等缩略图出现** → 再发提示词 → 等出图。

几个细节：

- 参考图存在扩展本地存储里，**不会上传到任何第三方服务器**，只在执行时喂给 ChatGPT 页面
- 大于 1.2MB 的图会自动压到 1600px 再存，避免手机原图把存储撑爆
- 每条任务都会**重新附加**一次参考图，不会复用上一条的附件（新对话里本来也没有）
- 附加失败会自动重试整条任务，不会悄悄丢掉参考图去生成一张不对的图
- 出图判定对带参考图的任务做了特殊处理：只认可「最后一条 assistant 消息之后」出现的图片，避免把你上传的参考图误当成生成结果下载下来
- 高级任务在「队列」页也会显示，带一个「图 N」标记

## 四、前提设定（不生成图片的提示词）

有些提示词不是让它画图，而是**铺垫前提**，比如「你是一位专业产品摄影师，接下来都按这个风格…」。这类内容不要放进队列，放进「前提」标签页。

**前提是按批次绑定的**：每个批次有自己独立的一套前提，互不影响。在「前提」页顶部的 **「绑定到哪个批次」** 下拉里，直接按批次名称选目标——比如选中「查找」，下面添加、删除、启停的所有操作都只作用于「查找」，不用先切回队列页换批次。下拉选项里会标出每个批次各有几条前提，下方还有一行总览。

- 默认选项是「跟随当前批次」：在队列页切到哪个批次，前提页就配置哪个批次
- 手动选中某个批次后会**锁定**到它，之后即使队列页切了别的批次，前提页仍然编辑你选中的那个
- 选回「跟随当前批次」即可恢复默认；被删除的批次会自动回落到默认

**它怎么工作：**

1. 每开一个新对话，扩展把这个批次的前提**逐条**发过去，每条都等 ChatGPT 回复
2. **每条前提（包括第一条和最后一条）发出后，必须检测到 ChatGPT 的回复、并且回复写完，才允许发下一条提示词**。判据是三件事：回复文字出现 → 「停止生成」消失 → 回复文本连续稳定。不是等一个拍脑袋的固定秒数。因为 ChatGPT 是乐观 UI——输入框一清空、气泡一挂上 DOM 就看起来"发成功了"，而新对话里第一条消息还伴随会话创建，紧接着发下一条会把前提挤掉，表现为前提完全没生效
3. 回复秒回也会补足「前提最小间隔」（默认 4 秒）防假完成；等不到回复按「等回复超时」（默认 60 秒）放行，**只记警告并继续，绝不重发前提、绝不把批次置异常**。消息节点选择器失效时会靠正文变化和文本稳定兜底
4. **最后一条前提之后同样要等回复**，之后才发第一条生图提示词；前提阶段完全不看图、不下载，就算模型顺手出图了也不会算进队列
5. 前提不进队列、不进进度条、不参与重试计数。设置里关掉「每条前提都等 ChatGPT 回复写完」开关，可回到只按最小间隔放行、不等回复的固定窗口模式
6. **ChatGPT 输出回复时，发送按钮会变成「停止生成」**。前提阶段既然已经等回复写完，正常路径不会再点停止；只有等回复超时仍残留「生成中」时才停掉它，避免正式生图提示词白等十几秒。正式生图阶段则只等待、绝不主动停止，避免截断正在生成的图片
7. 前提万一发送失败，批次**不会立刻变成「异常中断」**：任务自动退回并重试 2 次，连续 3 次才暂停，点「继续」即可恢复，不用重建批次

**几个要点：**

- 「同一对话连续生成」模式下，一个对话里只发一次前提（后面几条共用），不会重复发
- 「每条新开对话」和「并行」模式下，**每个新对话都会重新发一遍前提**——因为新对话没有上下文，不重发前提就丢失了
- 前提是一条一条加：写一条、点 ＋、清空再写，需要多条就重复几次
- 右上角「启用」开关只停用下拉选中的**那个批次**的前提，不影响其他批次，不用删内容

## 五、图片存到哪

每个批次分别决定自己的目录：

```
系统下载目录/
├── chatgpt-images/                 ← 设置里的「基础下载目录」
│   └── 批次_1105_2130/             ← 没单独指定目录的批次，用「基础目录/批次名」
│       └── 001_xxx.png
└── AI图/产品/                      ← 单独指定了目录的批次，直接用这个
    ├── 001_白色耳机柔和侧光.png
    └── 002_黑色手表浅景深.png
```

- **只能写到「下载目录」下面**。Chrome 扩展无权写入 `D://我的图//` 这种绝对路径
- **务必关掉 Chrome 设置里的「下载前询问每个文件的保存位置」**，否则每张图都弹一次另存为
- 文件名模板支持：`{index}`、`{index:03}`、`{slug}`、`{date}`、`{time}`、`{batch}`；中文原样保留
- **批次名称/下载子目录改完必须点「保存批次设置」**。队列页现在会直接显示「实际保存位置：系统下载目录 / xxx / 001_xxx.png」，有未保存修改也会提示，照着核对即可
- **一次生成多张图时默认只下载第一张**：产物按页面真实位置排序，取最靠前那张；第一张加载慢或重渲染时短暂消失都不会换图。日志会写「共 N 张，只下载第 1 张」。改这段前先跑 `tests/multi-image.test.js`
- **文件名不是靠 `downloads.download({filename})` 生效的**：只要扩展注册了 `onDeterminingFilename`（本扩展为了给附件卡片归位必须注册），Chrome 就会忽略传给 `download()` 的 filename（Chromium issue 579563）。所以 `downloads.js` 里维护一张「下载意图表」，三类下载都先登记目标路径，再在同一个监听器里同步 `suggest({filename})` 写回去；表同时写进 storage，SW 冷启动也能恢复。改这段前先跑 `tests/download-filename.test.js`

## 六、设置项

设置页最上方是**版本卡片**：显示当前运行版本（如 `v0.6.0`）、上次是从哪个版本更新来的、更新／重载生效时间、这个版本改了什么，以及最近 5 次版本记录。侧边栏顶部也有一个小版本号，点一下直接跳到这里。
版本号读的是**当前真正运行着的 `manifest.json`**，不是缓存里的字符串，所以：更新完在 `chrome://extensions` 重载扩展，设置页数字变了，就说明新代码已经生效；数字没变就是没重载。点「复制版本信息」可以把版本、更新说明与历史一次复制出来，反馈问题时直接贴。

| 项 | 说明 |
|---|---|
| 工作站点（批次设置） | 队列页「批次名称 / 下载子目录 / 工作站点」卡片里选 ChatGPT 或 Gemini，**改完点「保存批次设置」**。默认 ChatGPT；运行中锁定。新建批次继承当前选择 |
| 复制提示词 | 每条右侧「复制」= 该条完整原文；工具条「复制选中 / 复制全部」= 多条，按队列顺序以 `---` 分隔。原文从后台取，不受列表 240 字预览影响 |
| 会话策略 | **每条新开对话**（推荐）/ 同一对话连续 / 多对话并行。默认每条各开一个对话，所以聊天记录是分散的；想在一个页面里看完「提示词 + 图片」的完整对话流，改成「同一对话连续生成」 |
| 并行标签页数 | 仅并行模式生效（指单个批次内开几个标签页），默认 1，上限 3 |
| 基础下载目录 | 全局默认根目录；批次没单独指定目录时用它 + 批次名 |
| 一次生成多张图时 | **只下载第一张**（默认）：按页面上的先后顺序只保存第 1 张，其余不下载，一条任务仍然只产生一个文件。可切回「下载评分最高的一张」（旧行为，会挑尺寸最大或 4K 高清链接那张） |
| 间隔 | 两条任务之间的随机等待，避免触发风控 |
| 等前提回复 | 开关，默认开：每条前提都要检测到 ChatGPT 回复写完才发下一条（含第一条和最后一条）。关掉则只按最小间隔放行、不等回复 |
| 前提最小间隔 | 回复秒回也要补足的硬下限，默认 4 秒，防 ChatGPT 乐观 UI 的假完成 |
| 等回复超时 | 等不到回复最多等多久，默认 60 秒；超时只警告并继续，不重发、不判失败 |
| 单条超时 | 超过即判超时（默认 300 秒） |
| 失败重试 | 每条最多重试几次 |
| 未出图时 | 自动重试 / 直接失败 / 跳过 |
| 限额冷却 | 撞到生图上限后暂停多久（默认 60 分钟） |

## 七、必须知道的限制

1. **自动化操作官网可能触碰 OpenAI 使用条款**，也有触发 Cloudflare 人机校验的可能。风险是限流或账号受限，不保证绝对安全，建议先拿小号试一次。
2. **生图有配额**。跑到上限时扩展会自动熔断暂停，冷却结束自动恢复，不会硬撞。
3. **后台标签页会被 Chrome 节流**。出图检测用 MutationObserver 事件驱动；领任务则由页面 3~8 秒短轮询 + service worker 每 5 秒主动唤醒共同保证，即使标签页在后台、定时器被节流，卡住超过 15 秒也会被兜回。仍建议让 ChatGPT 窗口保持可见。
4. **页面改版会导致选择器失效**。站点 URL 事实在 `src/shared/sites.js`，DOM 候选链在 `src/shared/selectors.js`（按站点合并），出问题只改这两个文件。侧边栏「日志与诊断 → 运行自检」会直接告诉你哪一步断了，Gemini 还会额外报出「生成图容器 / 全尺寸下载按钮」命中数量。
5. **别同时开两个标签页跑同一个对话**，会互相抢消息。扩展会检测到并拒绝派发。
6. **Gemini 生图需要账号本身具备图片生成能力**。插件只是把提示词发给网页版并取回结果，无法控制模型一次出几张、也无法绕过站点本身的配额或地区限制。若 Gemini 只回复文字不出图，任务会按「未出图」策略处理（默认标待确认、不重发）。
7. **Gemini 的全尺寸下载依赖页面按钮**。若站点改成直接预览而不触发下载，日志会出现「全尺寸下载按钮未产生下载」并把该条标「待确认」，需要手动保存；插件不会因此重发提示词。

## 八、出问题了怎么查

侧边栏 →「日志与诊断」→「运行自检」，会逐项检查：

页面地址 / 登录状态 / 输入框存在 / 输入框可聚焦 / 输入链路可用 / 发送按钮选择器（可用状态 + 停止按钮是否已隔离）/ 对话容器 / 图片识别（URL 规则 + 宽松规则 + 页面图片样本）/ **文件产物识别（图片链接 + 附件卡片数量）** / 停止生成按钮 / 是否正在生成 / 限额提示 / 对话 ID / 页面语言 / 页面可见性

哪项打红叉，下面会直接给出修复提示。点「导出诊断」可以生成一份 JSON（含队列与日志）方便排查。

### 一键重置（卡住时先点这个）

侧边栏「队列」页控制区、或「设置 → 维护」里都有 **「一键重置」**。点一下就会：

- 停止所有批次，中止 ChatGPT 页面里正在跑的循环，并把所有批次状态归回「空闲」
- 清掉残留租约、僵尸标签页绑定、`attempt` 重试计数、连续失败计数、限额冷却、下载索引缓存
- 把「生成中 / 发送中 / 待确认 / 失败」的任务退回「待生成」；**已完成 / 已跳过保持原样，不会把下载好的图重跑一遍**
- 重新注入当前已打开的 ChatGPT 标签页脚本（**只复用，绝不新开标签页**），之后直接点「开始」即可，不用刷新页面、不用重建批次

**它不删任何用户数据**：批次、提示词、参考图、前提设定、下载目录、设置全部保留，日志也保留着方便回看。所以扩展更新后出现「异常中断」「等待派发」「前提发不出去」时，顺序是：`chrome://extensions` 重新加载扩展 → 点「一键重置」→ 点「开始」。

「设置 → 维护」里另有 **「清空全部数据」**（需再点一次确认）：恢复出厂设置，删除所有批次、提示词、参考图与日志，把设置恢复默认，并新建一个空批次。这个才是真正会丢数据的操作。

常见情况：

| 现象 | 原因与处理 |
|---|---|
| **任何卡住 / 异常中断 / 等待派发，不知道该点哪个** | 先点「一键重置」（见上一节）：清干净运行态、重新接管当前标签页，提示词一条不丢，然后点「开始」 |
| **说「运行中」但 ChatGPT 里什么都没发** | 页面连接断开：扩展重载后旧脚本失效、标签页归属丢失、或刚打开的页面脚本还没就绪。点「立即修复」会用**你当前正在看的 ChatGPT 标签页**重新接管并唤醒（不新开窗口）；后台也会自动重试 |
| **日志「已接管标签页 8038…」紧跟着「等待派发：这个标签页不是执行页」，然后几十秒不动** | **v0.5.1 已修**：上次运行遗留的后台标签页仍占着「执行页」绑定，但它根本不来领任务（停在错误页 / 脚本失效 / 被浏览器冻结）。旧逻辑只看 storage 里 `stale:false` 这个标记，就以为它活着，于是其它标签页全被 `no-batch` 拒绝，后台又只反复给那个死页发 WAKE。现在按「最后一次真正派发任务的时间」判定：超过正常间隔还没派发、且没有任务在生成时，当前正在轮询的标签页会自动接管并清掉旧绑定（日志写「改由当前标签页 X 接管…旧绑定已清除」）。有任务在生成时绝不接管，避免重复生图 |
| **点了「开始」很久没动静** | 先看「日志」页最后一行「等待派发：xxx」：`no-batch` = 这个标签页不是执行页（执行页超过正常间隔没来领任务时会自动接管），`no-composer` = 页面不是对话页，两者点「立即修复」都能处理。如果一个标签页都接管不了，会直接标为「异常中断」并提示刷新页面，不会再挂在「运行中」假状态 |
| **切到 Gemini 后一直「等待派发」，或日志出现「站点与批次绑定的站点不一致」** | 先在队列页把「工作站点」改成 Gemini 并**点「保存批次设置」**，再打开一个 `gemini.google.com` 对话页（不是 ChatGPT 页），必要时点「立即修复」。批次只接管同站点标签页，跨站点领任务会被明确拒绝，这是防止提示词发到错误网站的护栏 |
| **Gemini 出了图，但下载的是小尺寸预览 / 日志「全尺寸下载按钮未产生下载」** | Gemini 页面里是 `generated-image` 容器里的 1024px `blob:` 预览，插件优先点同容器的「Download full size image」拿全尺寸图，再由下载意图表归位到批次目录。看自检里「Gemini 生成图容器 / 全尺寸下载按钮」是否大于 0；为 0 说明前端改版，需更新 `selectors.js` 的 `generatedImageBox` / `imageDownloadButton`。若站点改成只预览不下载，该条会标「待确认」，请手动保存（**不要点一键重置**，否则会重复生图） |
| **复制出来的提示词只有前 240 字 / 复制按钮没反应** | 复制走后台 `GET_PROMPTS` 取完整原文，不会用列表里的预览。若完全没反应，多半是剪贴板权限：插件会先试 `navigator.clipboard`，失败自动退回 `execCommand('copy')`；仍失败时提示「复制失败，请检查剪贴板权限」，可改用「日志 → 导出诊断」间接核对 |
| **又自动开了新标签页** | 已修：只有「另一个批次此刻正在运行」才算标签页被占用；已停止/完成的旧归属不再挡路，会直接复用你现在开着的同站点标签页 |
| **看不到提示词被输入聊天框，但图片一直在出** | 正常。插件把整段文字一次性插进输入框后**立刻**点发送，文字只停留约 0.3 秒；默认「每条新开对话」，发完就切到下一个空白对话，所以盯着输入框很难看到那一条。图片能出，正说明 ChatGPT 收到了提示词。想看完整对话流，把「设置 → 会话策略」改成「同一对话连续生成」 |
| **有时正常、有时卡很久** | 旧版靠页面定时器，空闲轮询从 15 秒指数退避到 120 秒；MV3 的 service worker 空闲 30 秒被回收时又会丢消息，两者叠加成「越卡越久」。现在改成 3~8 秒短轮询（不封顶式退避）+ 后台每 5 秒主动唤醒 + 消息丢失立即补发 + 标签页归属丢失就地补绑定，最坏 15 秒被兜回 |
| 一直「待生成」，不动 | 没点「开始」，或 ChatGPT 标签页不在前台且被冻结；先跑一次自检 |
| **前提第一条就发不出去、报 `send-failed(...)`、批次变「异常状态」** | 根因是 ChatGPT 流式输出时发送按钮变成「停止生成」，旧版把它当发送按钮点，消息永远发不出去；而且一次失败就把整批打成异常中断。现在发送前会先恢复到可发送状态（前提阶段跳过文本回复、正式生图阶段只等待），失败会自动重试 2 次、连续 3 次才暂停。日志里会写明细分原因：`insert-failed`（文字没插进框）/ `submit-failed`（点了没反应）/ `send-button-disabled` / `only-stop-button` / `send-button-missing`，并附「输入框/框内字数/按钮候选/生成中/消息数」实况 |
| 提示「连续发送失败」 | 先看日志里的「发送诊断」那几行，按上面的细分原因判断；确认是选择器失效时改 `selectors.js` 里的 `composer` / `sendButton` / `stopButton`。批次现在只会**暂停**，点「继续」即可恢复，不用重建 |
| **网页已经生成了图，却显示「生成失败」，还反复生成好几张** | 见下方「出图识别失败」小节。根因是旧版靠 3 条图片 URL 白名单 + `naturalWidth≥200` 判图，ChatGPT 换了图片域名/用 blob/data URL 或图片晚于判定插入就全漏；加上租约过期回收不计数，`maxAttempts` 永远不触发，同一条能被无限次重发。现已全部修复 |
| **ChatGPT 给的是「xxx.png 图像」附件卡片 / 「查看 4K 高清原图」，日志却是 `img 4 / 新增 0 / 规则命中 0`** | 这不是没出图，是**产物形态不同**：页面上根本没有新增 `<img>`，旧版只扫图片必然判「未出图」。现在「链接 / 附件卡片」也算产物，日志会写成 `检测到 N 个产物（link/card）`；下载按 `http(s) 直链 → 页面内取流 → 点击附件并把下载归位到批次目录` 三级走。跑一次自检，看「文件产物识别」那一项是否大于 0 |
| **下载下来叫「下载.png」「下载 (1).png」，而且没进批次目录** | 这是 Chrome 的默认文件名，说明目标路径没写回去。旧版根因：扩展自己注册了 `onDeterminingFilename`，Chrome 因此忽略 `download({filename})`，而旧监听器又跳过扩展自己发起的下载。0.5.2 起用「下载意图表」统一归位，日志会出现 `#N 下载已归位 → 批次目录/001_xxx.png`；若仍不对，日志会有「实际落盘路径与设定不一致」并打印真实路径。另外确认 Chrome 没开「下载前询问每个文件的保存位置」、批次设置已点「保存批次设置」、以及没有其它下载管理类扩展在抢文件名 |
| 出图了但没下载 | 看日志有没有 `#N 已确认出图…开始下载` 和 `#N 已发起下载（直链 A / 数据 B，id=…）→ 路径`。有「已确认出图」但没「已发起下载」= 下载 API 调用失败或走的是附件点击链路（看 `#N 页面附件下载已归位 → 路径`）；两条都没有 = 根本没检测到图，按上一行排查。若出现 `附件点击未产生下载`，说明 ChatGPT 点卡片后只打开预览没触发下载，此时该条会标「待确认」，请手动保存那张图。也可查下载目录是否有同名/权限限制 |
| 高级任务提示「参考图附加失败」 | ChatGPT 的 file input 还没就绪或上传超时；看日志里的 reason，`no-file-input` 说明选择器要更新（`selectors.js`） |
| 卡在「生成中」很久 | 图生成本身慢，等出图期间每 30 秒会写一条进度日志；超时后默认标「待确认」，不会再自动重发提示词 |
| 一直是「待确认」 | 页面在生成过程中被刷新/关闭、图片晚于判定出现、或确实没出图。先看日志里的「诊断：img=… 新增=… 大图=…」，确认网页上到底有没有图，再看列表点「重试」 |

### 出图识别失败（为什么以前会重复生图）

三层原因，现在分别这样处理：

1. **判图规则太窄**。`probes.js` 现在不再把图片 URL 白名单当硬门槛，而是用「发送前全页面快照 → 发送后新出现的大图」做差集，再用尺寸/位置/alt 排除头像、图标、侧栏装饰图；`blob:` / `data:image/` / 任意 CDN 都能识别，扫描范围也从 `main` 扩到整个 `document`（新版 UI 会把图 portal 到 main 之外）。URL 白名单只用于排序和诊断。
2. **判定太急、URL 会变**。生成结束后给图片 20~45 秒晚到宽限期；签名 URL 每次重渲染会变，现在用去掉 query 的归一化签名，变化不再把稳定计时清零；`stopButton` 选择器万一失效，靠 DOM 静默兜底，不会悬到超时。判「未出图」时会把页面实况（`img / 新增 / 大图 / canvas / 消息 / 停止按钮` + 前几条 src）写进日志，一眼能定位。
3. **产物不只有 `<img>`**。ChatGPT 还会把结果作为「`xxx.png` / 图像」文件附件卡片，或「查看 4K 高清原图」的 `sandbox:` / `backend-api` 链接返回 —— 这时页面上连一个新增 `<img>` 都没有，日志就是 `img 4 新增 0 大图 0 规则命中 0`。现在 `probes.js` 统一产出三类产物（`img` / `link` / `card`），快照对链接和卡片也做差集，靠「图片扩展名 + 文件服务 URL + 图片语义文字」判定，并排除用户气泡里的参考图。后台按 `img > 高清原图链接 > 宽松 img > 附件卡片` 选产物：`http(s)` 直链直接下载，`sandbox:` / 卡片由页面内取流，取流失败则点击附件，再由 `chrome.downloads.onDeterminingFilename` 把页面触发的下载改到批次目录并登记归属；点击后始终没产生下载会超时标「待确认」，不会卡在「下载中」。
4. **失败处理会重发提示词**，重发就是重新生图。现在：`OUTCOME` 上报带确认与有限重试、后台对同一 token 幂等；租约过期/页面跳转都累加 `attempt` 并受 `maxAttempts` 约束；只要诊断显示页面上已有大图**或链接/附件产物**就直接标「待确认」不再重发；「设置 → 未出图时」默认改为 **「标记待确认，不重发（推荐）」**（旧配置会自动迁移一次，仍可手动改回自动重试）。

一句话：**宁可让你人工确认，也不再偷偷重发提示词多消耗一次生图额度。**

三个关键设计（改代码前请先看这三条）：

1. **Service Worker 是队列的唯一写者**，真相源在 `chrome.storage.local`，所有写入走 `withLock` 串行链。互斥来自 Promise 链，不来自 storage，所以绝对不能改成 `Promise.all` 并发读写。
2. **等待出图、等待下载完成都不能写成长期存活的 Promise**，必须「事件触发 + storage 持久化」，否则 SW 被回收就全丢。
3. **出图检测靠「发送前全页快照 → 发送后新出现的产物」的差集**，产物包括 `<img>`、图片链接、文件附件卡片三类；不能只认「最后一条 assistant 消息」，也不能只扫 `<img>`（附件卡片形态会全漏），更不能靠 URL 白名单硬判（ChatGPT 换域名就全漏）。快照必须同时记录 img / link / card 三类签名。全页扫之后必须用尺寸、位置、alt、图片语义与用户气泡/侧边栏排除装饰图和参考图，否则别的对话的缩略图会被抓错。
4. **图片快照在前提之后、正式提示词之前拍**：所以前提阶段即使出了图也会被差集排除掉，不会被误当成结果下载。
5. **前提节奏是「检测到回复写完」事件驱动，不是固定 sleep**：`src/content/premise.js` 是这段逻辑的唯一出处，content.js 只做适配。每条前提（含第一条和最后一条）之后都必须走 `waitForReply()`：回复文字出现 → 生成结束 → 文本稳定，再补足最小间隔；超时只能警告后继续，绝不能重发或把批次置异常。改这里前先跑 `tests/premise-pacing.test.js`。
6. **「执行页还活着」不能只看 `activeTabs` 里的 `stale:false`**：那只是 storage 里的一个标记，不代表页面真的在领任务。判定要看批次最后一次**真正派发出任务**的时间（`lastClaimAt`）以及有没有 ACTIVE 任务；超过正常间隔且没有任务在生成时才允许换执行页，接管时必须清掉旧绑定，否则会冒出两个执行页并行生图。改这段前先跑 `tests/zombie-tab.test.js`。
7. **文件名只能由 `onDeterminingFilename` 的 `suggest()` 决定**：因为本扩展注册了这个监听器，`chrome.downloads.download({filename})` 会被 Chrome 忽略（Chromium 579563），`data:` URL 尤其明显。所有下载路径都必须先 `armIntent()` 登记到意图表（内存 + `chrome.storage.local`），监听器对自己发起的下载也要同步 `suggest`；异步从 storage 恢复时监听器必须 `return true`，且 `suggest` 只能调一次。改这段前先跑 `tests/download-filename.test.js`。
8. **「第一张」由页面 DOM 顺序决定，不由评分或加载速度决定**：`probes.sortByDom()` 给产物写 `order`（0 = 第一张），`watcher.js` 跨轮询轮次锁定首图并保留纯数据副本，上报前必须过 `cleanArtifacts()` 剥离 DOM 节点（否则 `sendMessage` 结构化克隆会失败、任务被退回重发）。后台 `pickArtifact()` 默认只取 `order=0`，`multiImage='best'` 才回到评分策略；两种策略下一条任务都只发起一次下载。改这段前先跑 `tests/multi-image.test.js`。
9. **站点 URL 事实只在 `sites.js`，DOM 候选链只在 `selectors.js`**：加站点或改版时不要在 composer / tabpool / service-worker 里写死域名。`selectors.js` 在加载时按 `currentSiteId()` 把「站点专属 → 通用兜底 → ChatGPT 老候选」合成 `CGR.SEL`，所以内容层不需要知道自己跑在哪个网站。批次 `site` 字段决定 `tabpool.ensureBatchTabs()` 挑哪些标签页，`claim()` 会拒绝站点不一致的领任务请求（有任务在生成时也不会跨站点接管）。改这段前先跑 `tests/site-adapter.test.js`。
10. **复制提示词必须取后台原文**：`publishView()` 的 `compact()` 把 `prompt` 截成 240 字，任何复制入口都不能直接用视图里的 `p`。走 `CMD.GET_PROMPTS` → `store.getPrompts()` → `CGR.PROMPT_COPY`，剪贴板 API 不可用时由 `execCommand('copy')` 兜底。改这段前先跑 `tests/prompt-copy.test.js`。

## 十、版本与发版规范

**版本号只有一个来源**：`manifest.json` 的 `version`。侧边栏通过 `chrome.runtime.getManifest().version` 直接读当前真正运行着的代码；`src/shared/version.js` 不硬编码当前版本，只维护每个版本的更新说明（`RELEASES`）与版本变化的计算逻辑。

每次改完代码发版，必须做三步：

1. `manifest.json` 的 `version` +1（如 `0.5.0` → `0.5.1`）
2. 在 `src/shared/version.js` 的 `RELEASES` **顶部**补一条同版本记录：`version` / `date` / `title` / `changes`
3. 跑 `node tests/version.test.js`（或全量 `for f in tests/*.test.js; do node "$f"; done`）。两步的版本号不一致会直接失败，设置页也会显示「缺少更新说明」

提交推送后，在 `chrome://extensions` 重新加载扩展并刷新对应站点的对话页。Service Worker 的 `onInstalled` 会把「从 vX 更新到 vY、什么时间」写进 `chrome.storage.local` 的 `cgrVersion`；SW 冷启动会兜底补记漏掉的升级，同版本重载只刷新生效时间、不会重复记一条更新（恢复出厂设置后会重建这条记录，因为它不是用户数据）。设置页的版本卡片和顶部徽标随即显示新版本号。

> 想确认「更新到底生效没有」，只看设置页的版本数字：变了就是新代码在跑，没变就是还没重载。点「复制版本信息」会把版本号、更新说明、历史记录拼成文本，排障时直接贴出来。
