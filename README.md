# ChatGPT 批量生图助手（Chrome 扩展）

把一整批提示词丢给 ChatGPT 官网，它逐条自动生图、自动判断这张图好了没有、自动下载到指定文件夹，然后接着跑下一条，直到全部完成。

不需要 API Key，走的是你自己已登录的 chatgpt.com 页面。

---

## 一、安装

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（含 `manifest.json` 的那一层）
4. 在 chrome 工具栏点扩展图标 → 右侧弹出侧边栏

> 需要 Chrome 114 及以上。

## 二、批次（分组）与简单模式

### 先建批次

侧边栏顶部的下拉框就是批次切换器。一个批次 = 一个主题 / 一个任务，它自己带着：

- **名称**（同时决定默认下载子目录）
- **下载目录**（可以单独指定，留空就是 `基础目录/批次名/`）
- **前提设定**（这个批次专属的上下文，见第四节）
- **运行状态**、**独立窗口**

点「＋ 新建」建一个，再在下方改名和设目录，点「保存批次设置」。不同主题（产品图 / 风景图 / 客户A）就建不同批次，互不干扰。

### 再往里加提示词

1. 输入框写一条提示词，点右侧 **＋**，加入**当前选中的批次**，输入框自动清空
   - `Ctrl + Enter` / `⌘ + Enter` 等同于点 ＋；`Shift + Enter` 换行
2. 重复加到你满意为止
3. 点「开始」，它会**直接在你已经打开的那个 ChatGPT 标签页里跑**，不会新开窗口

> 只有当你没有可用的 ChatGPT 标签页时才会新建一个（建在当前窗口里，不另开窗口）。
> 同时跑多个批次时，每个批次占一个标签页：先占用空闲的 ChatGPT 标签页，不够才再开。

跑的过程中：

- 每个条目显示状态：待生成 / 发送中 / 生成中 / 下载中 / 已完成 / 失败 / 待确认
- 单条操作：「重试」「跑这条」「跳过」
- 左侧复选框 + 「删除选中」批量删除（二次确认，执行中的不能删）
- 「清理」移除已完成 / 失败 / 跳过
- 「暂停」＝ 当前这张跑完就停；「停止」＝ 立刻中断并退回待生成

## 三、高级模式：提示词 + 参考图

侧边栏第二个标签页「高级」，用法和简单模式一样，只是可以额外挂参考图。

1. 写提示词
2. 加参考图，三种方式任选：点「＋ 参考图」选文件、把图片拖进页面、或者**直接 Ctrl+V 粘贴**（截图工具截完就能贴）。最多 4 张，缩略图列在下面，点 × 可移除
3. 点 **＋** 加入队列 —— 提示词和图片就绑定成一条任务

执行时：先打开新对话 → 发前提（如果配了）→ **把参考图上传到输入框并等缩略图出现** → 再发提示词 → 等出图。

几个细节：

- 参考图存在扩展本地存储里，**不会上传到任何第三方服务器**，只在执行时喂给 ChatGPT 页面
- 大于 1.2MB 的图会自动压到 1600px 再存，避免手机原图把存储撑爆
- 每条任务都会**重新附加**一次参考图，不会复用上一条的附件（新对话里本来也没有）
- 附加失败会自动重试整条任务，不会悄悄丢掉参考图去生成一张不对的图
- 出图判定对带参考图的任务做了特殊处理：只认可「最后一条 assistant 消息之后」出现的图片，避免把你上传的参考图误当成生成结果下载下来
- 高级任务在「队列」页也会显示，带一个「图 N」标记

## 四、前提设定（不生成图片的提示词）

有些提示词不是让它画图，而是**铺垫前提**，比如「你是一位专业产品摄影师，接下来都按这个风格…」。这类内容不要放进队列，放进「前提」标签页。

**前提是按批次存的**：每个批次有自己的一套前提，切换批次后这里编辑的就是那个批次的前提，互不影响。

**它怎么工作：**

1. 每开一个新对话（每条新开对话 / 每个并行窗口的每张图），扩展会先把前提**逐条**发过去，发一条等模型答完再发下一条
2. 前提阶段**完全不看图**：就算模型顺手出图了，也不会下载，更不会算进队列
3. 所有前提都拿到回复后，才开始发第 N 条正式的生图提示词
4. 前提不进队列、不进进度条、不参与重试计数

**几个要点：**

- 「同一对话连续生成」模式下，一个对话里只发一次前提（后面几条共用），不会重复发
- 「每条新开对话」和「并行」模式下，**每个新对话都会重新发一遍前提**——因为新对话没有上下文，不重发前提就丢失了。所以：`N 条图 × M 条前提` 会多出 `N×M` 次往返，队列长的时候耗时明显增加
- 前提的等待上限是 120 秒（可在 `src/shared/constants.js` 的 `premiseTimeoutMs` 调），超时会中止整个队列并提示，不会默默跳过
- 前提也是一条一条加：写一条、点 ＋、清空再写。需要多条就重复几次，不建议把多个设定塞进同一条
- 右上角「启用」开关可以临时停用前提，不用删内容

## 五、图片存到哪

每个批次分别决定自己的目录：

```
系统下载目录/
├── chatgpt-images/                 ← 设置里的「基础下载目录」
│   └── 批次_1105_2130/             ← 没单独指定目录的批次，用「基础目录/批次名」
│       └── 001_xxx.png
└── AI图/产品/                      ← 单独指定了目录的批次，直接用这个
    ├── 001_白色耳机柔和侧光.png
    └── 002_黑色手表浅景深.png
```

- **只能写到「下载目录」下面**。Chrome 扩展无权写入 `D://我的图//` 这种绝对路径
- **务必关掉 Chrome 设置里的「下载前询问每个文件的保存位置」**，否则每张图都弹一次另存为
- 文件名模板支持：`{index}`、`{index:03}`、`{slug}`、`{date}`、`{time}`、`{batch}`；中文原样保留

## 六、设置项

| 项 | 说明 |
|---|---|
| 会话策略 | **每条新开对话**（推荐）/ 同一对话连续 / 多对话并行 |
| 并行标签页数 | 仅并行模式生效（指单个批次内开几个标签页），默认 1，上限 3 |
| 基础下载目录 | 全局默认根目录；批次没单独指定目录时用它 + 批次名 |
| 间隔 | 两条任务之间的随机等待，避免触发风控 |
| 单条超时 | 超过即判超时（默认 300 秒） |
| 失败重试 | 每条最多重试几次 |
| 未出图时 | 自动重试 / 直接失败 / 跳过 |
| 限额冷却 | 撞到生图上限后暂停多久（默认 60 分钟） |

## 七、必须知道的限制

1. **自动化操作官网可能触碰 OpenAI 使用条款**，也有触发 Cloudflare 人机校验的可能。风险是限流或账号受限，不保证绝对安全，建议先拿小号试一次。
2. **生图有配额**。跑到上限时扩展会自动熔断暂停，冷却结束自动恢复，不会硬撞。
3. **后台标签页会被 Chrome 节流**。检测逻辑用 MutationObserver 事件驱动规避了这个问题，但串行模式仍建议让 ChatGPT 窗口保持可见（最小化可以）。
4. **页面改版会导致选择器失效**。所有选择器集中在 `src/shared/selectors.js`，出问题只改这一个文件。侧边栏「日志与诊断 → 运行自检」会直接告诉你哪一步断了。
5. **别同时开两个标签页跑同一个对话**，会互相抢消息。扩展会检测到并拒绝派发。

## 八、出问题了怎么查

侧边栏 →「日志与诊断」→「运行自检」，会逐项检查：

页面地址 / 登录状态 / 输入框存在 / 输入框可聚焦 / 输入链路可用 / 发送按钮 / 对话容器 / 图片识别规则 / 是否正在生成 / 限额提示 / 对话 ID / 页面语言 / 页面可见性

哪项打红叉，下面会直接给出修复提示。点「导出诊断」可以生成一份 JSON（含队列与日志）方便排查。

常见情况：

| 现象 | 原因与处理 |
|---|---|
| **说「运行中」但 ChatGPT 里什么都没发** | 最常见：扩展更新/重载后，已打开的页面里还是旧的内容脚本，后台消息全部落空。现在会自动检测并弹出黄色提示条，点「立即修复」即可（等同刷新页面）；如果没弹，手动刷新一次 ChatGPT 页面 |
| 一直「待生成」，不动 | 没点「开始」，或 ChatGPT 标签页不在前台且被冻结；先跑一次自检 |
| 提示「连续发送失败」 | 输入框结构变了，改 `selectors.js` 里的 `composer` / `sendButton` |
| 出图了但没下载 | 看日志是否走了「页面内取流」；检查下载目录是否存在同名权限限制 |
| 高级任务提示「参考图附加失败」 | ChatGPT 的 file input 还没就绪或上传超时；看日志里的 reason，`no-file-input` 说明选择器要更新（`selectors.js`） |
| 卡在「生成中」很久 | 图生成本身慢；超时后会自动判超时并重试 |
| 一直是「待确认」 | 页面在生成过程中被刷新/关闭了，图片可能已出但没抓到，手动看一眼再点「重试」 |

## 九、代码结构

```
manifest.json                  MV3 配置
src/shared/                    content 与 SW 共用（IIFE 挂 globalThis.CGR，零构建）
  constants.js                 状态枚举 / 消息类型 / 默认配置
  selectors.js                 ★ 全部 DOM 选择器（改版只改这里）
  slug.js                      文件名 slug 化、模板渲染、目录校验
  sched.js                     睡眠 / 节流 / 轮询 / 超时包装
src/background/
  service-worker.js            入口，只做事件注册与转发
  store.js                     storage 单写者 + withLock 串行锁 + 视图发布
  orchestrator.js              队列推进、全局状态机、结果处理
  lease.js                     租约签发 / 续租 / 回收（防两个标签页抢同一条）
  downloads.js                 三级下载降级链 + 下载状态推进
  tabpool.js                   标签页池（串行复用 / 并行独立窗口）
  scheduler.js                 每 30 秒扫描：心跳、续租、限额恢复
src/content/
  content.js                   主循环：领任务 → 新开对话 → 发送 → 等出图 → 上报
  composer.js                  ProseMirror 输入与发送（三级插入兜底）
  watcher.js                   ★ 出图检测（快照差集 + src 稳定 + 停止按钮消失）
  probes.js                    生成中 / 限额 / 报错 / 登录墙探测
  selfcheck.js                 13 项自检
src/sidepanel/                 侧边栏 UI
```

三个关键设计（改代码前请先看这三条）：

1. **Service Worker 是队列的唯一写者**，真相源在 `chrome.storage.local`，所有写入走 `withLock` 串行链。互斥来自 Promise 链，不来自 storage，所以绝对不能改成 `Promise.all` 并发读写。
2. **等待出图、等待下载完成都不能写成长期存活的 Promise**，必须「事件触发 + storage 持久化」，否则 SW 被回收就全丢。
3. **出图检测必须用 `main` 范围内的集合差集**，不能找「最后一条 assistant 消息」——生成图不在那条消息里；也不能全页扫——别的标签页生成完会弹一个带缩略图的通知，会抓错图。
4. **前提设定在正式任务之前、快照之后拍**：发完前提再给正式任务拍图片快照，所以前提阶段即使出了图也会被差集排除掉，不会被误当成结果下载。
