# ChatGPT 批量生图助手（Chrome 扩展）

把一整批提示词丢给 ChatGPT 官网，它逐条自动生图、自动判断这张图好了没有、自动下载到指定文件夹，然后接着跑下一条，直到全部完成。

不需要 API Key，走的是你自己已登录的 chatgpt.com 页面。

---

## 一、安装

1. 打开 Chrome，地址栏输入 `chrome://extensions`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选择本目录（含 `manifest.json` 的那一层）
4. 在 chrome 工具栏点扩展图标 → 右侧弹出侧边栏

> 需要 Chrome 114 及以上。

## 二、批次（分组）与简单模式

### 先建批次

侧边栏顶部的下拉框就是批次切换器。一个批次 = 一个主题 / 一个任务，它自己带着：

- **名称**（同时决定默认下载子目录）
- **下载目录**（可以单独指定，留空就是 `基础目录/批次名/`）
- **前提设定**（这个批次专属的上下文，见第四节）
- **运行状态**、**独立窗口**

点「＋ 新建」建一个，再在下方改名和设目录，点「保存批次设置」。不同主题（产品图 / 风景图 / 客户A）就建不同批次，互不干扰。

### 再往里加提示词

**方式一：一条一条加**

1. 输入框写一条提示词，点右侧 **＋**，加入**当前选中的批次**，输入框自动清空
   - `Ctrl + Enter` / `⌘ + Enter` 等同于点 ＋；`Shift + Enter` 换行
2. 重复加到你满意为止

**方式二：从 Markdown 批量导入**

点输入框下方的「从 Markdown 导入」，会弹出一个导入面板，三条路随便走：

- 点「选择文件」上传 `.md` / `.markdown` / `.txt`
- 把文件直接拖进虚线框
- 把 Markdown 内容粘进去（面板里按 `Ctrl+V`，或贴在文本框里）

规则只有一条：**一个代码块 = 一条提示词**，代码块里的内容就是这条提示词的正文；文件里有几个代码块，就导入几条。

````markdown
```
白色无线耳机，柔和侧光，浅景深
```

```
黑色石英手表，深色大理石台面
```
````

上面这段会导入 2 条。几个细节：

- 代码块前面的标题、说明文字、列表都不参与，只取代码块内部
- 代码块里写了语言标记（```text）不影响，照样只取正文
- 用四个反引号包住三个反引号，可以正常保留提示词里自带的 ``` 片段
- 代码块内部的首尾空行会被去掉，中间换行保留
- 没闭合的代码块按「一直到文末」处理，并提示你
- 空代码块会被忽略，不会产生空任务
- 导入前会显示「识别到 N 条」和前 8 条的预览，先核对再点「导入」
- 导入是**追加**到当前批次末尾，不会清空已有提示词；单批次上限 2000 条

3. 点「开始」，它会**直接在你已经打开的那个 ChatGPT 标签页里跑**，不会新开窗口

> 只有当你没有可用的 ChatGPT 标签页时才会新建一个（建在当前窗口里，不另开窗口）。
> 同时跑多个批次时，每个批次占一个标签页：先占用空闲的 ChatGPT 标签页，不够才再开。

跑的过程中：

- 每个条目显示状态：待生成 / 发送中 / 生成中 / 下载中 / 已完成 / 失败 / 待确认
- 单条操作：「重试」「跑这条」「跳过」
- 左侧复选框 + 「删除选中」批量删除（二次确认，执行中的不能删）
- 「清理」移除已完成 / 失败 / 跳过
- 「暂停」＝ 当前这张跑完就停；「停止」＝ 立刻中断并退回待生成

## 三、高级模式：提示词 + 参考图

侧边栏第二个标签页「高级」，用法和简单模式一样，只是可以额外挂参考图。

1. 写提示词
2. 加参考图，三种方式任选：点「＋ 参考图」选文件、把图片拖进页面、或者**直接 Ctrl+V 粘贴**（截图工具截完就能贴）。最多 4 张，缩略图列在下面，点 × 可移除
3. 点 **＋** 加入队列 —— 提示词和图片就绑定成一条任务

执行时：先打开新对话 → 发前提（如果配了）→ **把参考图上传到输入框并等缩略图出现** → 再发提示词 → 等出图。

几个细节：

- 参考图存在扩展本地存储里，**不会上传到任何第三方服务器**，只在执行时喂给 ChatGPT 页面
- 大于 1.2MB 的图会自动压到 1600px 再存，避免手机原图把存储撑爆
- 每条任务都会**重新附加**一次参考图，不会复用上一条的附件（新对话里本来也没有）
- 附加失败会自动重试整条任务，不会悄悄丢掉参考图去生成一张不对的图
- 出图判定对带参考图的任务做了特殊处理：只认可「最后一条 assistant 消息之后」出现的图片，避免把你上传的参考图误当成生成结果下载下来
- 高级任务在「队列」页也会显示，带一个「图 N」标记

## 四、前提设定（不生成图片的提示词）

有些提示词不是让它画图，而是**铺垫前提**，比如「你是一位专业产品摄影师，接下来都按这个风格…」。这类内容不要放进队列，放进「前提」标签页。

**前提是按批次绑定的**：每个批次有自己独立的一套前提，互不影响。在「前提」页顶部的 **「绑定到哪个批次」** 下拉里，直接按批次名称选目标——比如选中「查找」，下面添加、删除、启停的所有操作都只作用于「查找」，不用先切回队列页换批次。下拉选项里会标出每个批次各有几条前提，下方还有一行总览。

- 默认选项是「跟随当前批次」：在队列页切到哪个批次，前提页就配置哪个批次
- 手动选中某个批次后会**锁定**到它，之后即使队列页切了别的批次，前提页仍然编辑你选中的那个
- 选回「跟随当前批次」即可恢复默认；被删除的批次会自动回落到默认

**它怎么工作：**

1. 每开一个新对话，扩展把这个批次的前提**逐条**发过去；**发出去就算完成，不等模型回复**，也不看内容
2. 前提阶段**完全不看图**：就算模型顺手出图了，也不会下载，更不会算进队列
3. 发完前提就开始发正式的生图提示词
4. 前提不进队列、不进进度条、不参与重试计数
5. **ChatGPT 输出回复时，发送按钮会变成「停止生成」**。此时任何点击都只会中止回复、消息发不出去，所以每条前提发送前会先把输入框恢复到可发送状态：前提阶段直接跳过正在输出的文本回复（用户消息已经进入对话历史，回复内容对铺垫上下文没有影响），**不等待回复、也不看生成结果**；正式生图阶段则只等待、绝不主动停止，避免截断正在生成的图片
6. 前提万一发送失败，批次**不会立刻变成「异常中断」**：任务自动退回并重试 2 次，连续 3 次才暂停，点「继续」即可恢复，不用重建批次

**几个要点：**

- 「同一对话连续生成」模式下，一个对话里只发一次前提（后面几条共用），不会重复发
- 「每条新开对话」和「并行」模式下，**每个新对话都会重新发一遍前提**——因为新对话没有上下文，不重发前提就丢失了
- 前提是一条一条加：写一条、点 ＋、清空再写，需要多条就重复几次
- 右上角「启用」开关只停用下拉选中的**那个批次**的前提，不影响其他批次，不用删内容

## 五、图片存到哪

每个批次分别决定自己的目录：

```
系统下载目录/
├── chatgpt-images/                 ← 设置里的「基础下载目录」
│   └── 批次_1105_2130/             ← 没单独指定目录的批次，用「基础目录/批次名」
│       └── 001_xxx.png
└── AI图/产品/                      ← 单独指定了目录的批次，直接用这个
    ├── 001_白色耳机柔和侧光.png
    └── 002_黑色手表浅景深.png
```

- **只能写到「下载目录」下面**。Chrome 扩展无权写入 `D://我的图//` 这种绝对路径
- **务必关掉 Chrome 设置里的「下载前询问每个文件的保存位置」**，否则每张图都弹一次另存为
- 文件名模板支持：`{index}`、`{index:03}`、`{slug}`、`{date}`、`{time}`、`{batch}`；中文原样保留

## 六、设置项

| 项 | 说明 |
|---|---|
| 会话策略 | **每条新开对话**（推荐）/ 同一对话连续 / 多对话并行。默认每条各开一个对话，所以聊天记录是分散的；想在一个页面里看完「提示词 + 图片」的完整对话流，改成「同一对话连续生成」 |
| 并行标签页数 | 仅并行模式生效（指单个批次内开几个标签页），默认 1，上限 3 |
| 基础下载目录 | 全局默认根目录；批次没单独指定目录时用它 + 批次名 |
| 间隔 | 两条任务之间的随机等待，避免触发风控 |
| 单条超时 | 超过即判超时（默认 300 秒） |
| 失败重试 | 每条最多重试几次 |
| 未出图时 | 自动重试 / 直接失败 / 跳过 |
| 限额冷却 | 撞到生图上限后暂停多久（默认 60 分钟） |

## 七、必须知道的限制

1. **自动化操作官网可能触碰 OpenAI 使用条款**，也有触发 Cloudflare 人机校验的可能。风险是限流或账号受限，不保证绝对安全，建议先拿小号试一次。
2. **生图有配额**。跑到上限时扩展会自动熔断暂停，冷却结束自动恢复，不会硬撞。
3. **后台标签页会被 Chrome 节流**。出图检测用 MutationObserver 事件驱动；领任务则由页面 3~8 秒短轮询 + service worker 每 5 秒主动唤醒共同保证，即使标签页在后台、定时器被节流，卡住超过 15 秒也会被兜回。仍建议让 ChatGPT 窗口保持可见。
4. **页面改版会导致选择器失效**。所有选择器集中在 `src/shared/selectors.js`，出问题只改这一个文件。侧边栏「日志与诊断 → 运行自检」会直接告诉你哪一步断了。
5. **别同时开两个标签页跑同一个对话**，会互相抢消息。扩展会检测到并拒绝派发。

## 八、出问题了怎么查

侧边栏 →「日志与诊断」→「运行自检」，会逐项检查：

页面地址 / 登录状态 / 输入框存在 / 输入框可聚焦 / 输入链路可用 / 发送按钮选择器（可用状态 + 停止按钮是否已隔离）/ 对话容器 / 图片识别（URL 规则 + 宽松规则 + 页面图片样本）/ 停止生成按钮 / 是否正在生成 / 限额提示 / 对话 ID / 页面语言 / 页面可见性

哪项打红叉，下面会直接给出修复提示。点「导出诊断」可以生成一份 JSON（含队列与日志）方便排查。

### 一键重置（卡住时先点这个）

侧边栏「队列」页控制区、或「设置 → 维护」里都有 **「一键重置」**。点一下就会：

- 停止所有批次，中止 ChatGPT 页面里正在跑的循环，并把所有批次状态归回「空闲」
- 清掉残留租约、僵尸标签页绑定、`attempt` 重试计数、连续失败计数、限额冷却、下载索引缓存
- 把「生成中 / 发送中 / 待确认 / 失败」的任务退回「待生成」；**已完成 / 已跳过保持原样，不会把下载好的图重跑一遍**
- 重新注入当前已打开的 ChatGPT 标签页脚本（**只复用，绝不新开标签页**），之后直接点「开始」即可，不用刷新页面、不用重建批次

**它不删任何用户数据**：批次、提示词、参考图、前提设定、下载目录、设置全部保留，日志也保留着方便回看。所以扩展更新后出现「异常中断」「等待派发」「前提发不出去」时，顺序是：`chrome://extensions` 重新加载扩展 → 点「一键重置」→ 点「开始」。

「设置 → 维护」里另有 **「清空全部数据」**（需再点一次确认）：恢复出厂设置，删除所有批次、提示词、参考图与日志，把设置恢复默认，并新建一个空批次。这个才是真正会丢数据的操作。

常见情况：

| 现象 | 原因与处理 |
|---|---|
| **任何卡住 / 异常中断 / 等待派发，不知道该点哪个** | 先点「一键重置」（见上一节）：清干净运行态、重新接管当前标签页，提示词一条不丢，然后点「开始」 |
| **说「运行中」但 ChatGPT 里什么都没发** | 页面连接断开：扩展重载后旧脚本失效、标签页归属丢失、或刚打开的页面脚本还没就绪。侧边栏会弹黄色提示条，点「立即修复」会复用当前标签页重新接管并唤醒（不新开窗口）；后台每 30 秒也会自动重试一次 |
| **点了「开始」很久没动静** | 先看「日志」页最后一行「等待派发：xxx」：`no-batch` = 这个标签页没绑定批次，`no-composer` = 页面不是对话页，两者点「立即修复」都能处理。如果一个标签页都接管不了，现在会直接标为「异常中断」并提示刷新页面，不会再挂在「运行中」假状态 |
| **又自动开了新标签页** | 已修：只有「另一个批次此刻正在运行」才算标签页被占用；已停止/完成的旧归属不再挡路，会直接复用你现在开着的 ChatGPT 标签页 |
| **看不到提示词被输入聊天框，但图片一直在出** | 正常。插件把整段文字一次性插进输入框后**立刻**点发送，文字只停留约 0.3 秒；默认「每条新开对话」，发完就切到下一个空白对话，所以盯着输入框很难看到那一条。图片能出，正说明 ChatGPT 收到了提示词。想看完整对话流，把「设置 → 会话策略」改成「同一对话连续生成」 |
| **有时正常、有时卡很久** | 旧版靠页面定时器，空闲轮询从 15 秒指数退避到 120 秒；MV3 的 service worker 空闲 30 秒被回收时又会丢消息，两者叠加成「越卡越久」。现在改成 3~8 秒短轮询（不封顶式退避）+ 后台每 5 秒主动唤醒 + 消息丢失立即补发 + 标签页归属丢失就地补绑定，最坏 15 秒被兜回 |
| 一直「待生成」，不动 | 没点「开始」，或 ChatGPT 标签页不在前台且被冻结；先跑一次自检 |
| **前提第一条就发不出去、报 `send-failed(...)`、批次变「异常状态」** | 根因是 ChatGPT 流式输出时发送按钮变成「停止生成」，旧版把它当发送按钮点，消息永远发不出去；而且一次失败就把整批打成异常中断。现在发送前会先恢复到可发送状态（前提阶段跳过文本回复、正式生图阶段只等待），失败会自动重试 2 次、连续 3 次才暂停。日志里会写明细分原因：`insert-failed`（文字没插进框）/ `submit-failed`（点了没反应）/ `send-button-disabled` / `only-stop-button` / `send-button-missing`，并附「输入框/框内字数/按钮候选/生成中/消息数」实况 |
| 提示「连续发送失败」 | 先看日志里的「发送诊断」那几行，按上面的细分原因判断；确认是选择器失效时改 `selectors.js` 里的 `composer` / `sendButton` / `stopButton`。批次现在只会**暂停**，点「继续」即可恢复，不用重建 |
| **网页已经生成了图，却显示「生成失败」，还反复生成好几张** | 见下方「出图识别失败」小节。根因是旧版靠 3 条图片 URL 白名单 + `naturalWidth≥200` 判图，ChatGPT 换了图片域名/用 blob/data URL 或图片晚于判定插入就全漏；加上租约过期回收不计数，`maxAttempts` 永远不触发，同一条能被无限次重发。现已全部修复 |
| 出图了但没下载 | 看日志有没有 `#N 已确认出图…开始下载` 和 `#N 已发起下载（直链 A / 数据 B，id=…）→ 路径`。有「已确认出图」但没「已发起下载」= 下载 API 调用失败，看后面的错误日志；两条都没有 = 根本没检测到图，按上一行排查。也可查下载目录是否有同名/权限限制 |
| 高级任务提示「参考图附加失败」 | ChatGPT 的 file input 还没就绪或上传超时；看日志里的 reason，`no-file-input` 说明选择器要更新（`selectors.js`） |
| 卡在「生成中」很久 | 图生成本身慢，等出图期间每 30 秒会写一条进度日志；超时后默认标「待确认」，不会再自动重发提示词 |
| 一直是「待确认」 | 页面在生成过程中被刷新/关闭、图片晚于判定出现、或确实没出图。先看日志里的「诊断：img=… 新增=… 大图=…」，确认网页上到底有没有图，再看列表点「重试」 |

### 出图识别失败（为什么以前会重复生图）

三层原因，现在分别这样处理：

1. **判图规则太窄**。`probes.js` 现在不再把图片 URL 白名单当硬门槛，而是用「发送前全页面快照 → 发送后新出现的大图」做差集，再用尺寸/位置/alt 排除头像、图标、侧栏装饰图；`blob:` / `data:image/` / 任意 CDN 都能识别，扫描范围也从 `main` 扩到整个 `document`（新版 UI 会把图 portal 到 main 之外）。URL 白名单只用于排序和诊断。
2. **判定太急、URL 会变**。生成结束后给图片 20~45 秒晚到宽限期；签名 URL 每次重渲染会变，现在用去掉 query 的归一化签名，变化不再把稳定计时清零；`stopButton` 选择器万一失效，靠 DOM 静默兜底，不会悬到超时。判「未出图」时会把页面实况（`img / 新增 / 大图 / canvas / 消息 / 停止按钮` + 前几条 src）写进日志，一眼能定位。
3. **失败处理会重发提示词**，重发就是重新生图。现在：`OUTCOME` 上报带确认与有限重试、后台对同一 token 幂等；租约过期/页面跳转都累加 `attempt` 并受 `maxAttempts` 约束；只要诊断显示页面上已有大图就直接标「待确认」不再重发；「设置 → 未出图时」默认改为 **「标记待确认，不重发（推荐）」**（旧配置会自动迁移一次，仍可手动改回自动重试）。

一句话：**宁可让你人工确认，也不再偷偷重发提示词多消耗一次生图额度。**

改发送、出图检测或结果处理前请跑对应测试，避免又退回「前提发不出去」或「已出图却判失败 → 重复生图」。

三个关键设计（改代码前请先看这三条）：

1. **Service Worker 是队列的唯一写者**，真相源在 `chrome.storage.local`，所有写入走 `withLock` 串行链。互斥来自 Promise 链，不来自 storage，所以绝对不能改成 `Promise.all` 并发读写。
2. **等待出图、等待下载完成都不能写成长期存活的 Promise**，必须「事件触发 + storage 持久化」，否则 SW 被回收就全丢。
3. **出图检测靠「发送前全页快照 → 发送后新出现的大图」的差集**，不能只认「最后一条 assistant 消息」（生成图不在那条里），也不能靠 URL 白名单硬判（ChatGPT 换域名就全漏）。全页扫之后必须用尺寸、位置、alt 与用户气泡/侧边栏排除装饰图和参考图，否则别的对话的缩略图会被抓错。
4. **前提设定在正式任务之前、快照之后拍**：发完前提再给正式任务拍图片快照，所以前提阶段即使出了图也会被差集排除掉，不会被误当成结果下载。
